# Лабораторная работа 10. Потоки, процессы, Cython, отпускание GIL

## О чём эта работа простыми словами

Есть функция, которая численно считает интеграл (площадь под графиком)
методом прямоугольников — обычный цикл `for` в чистом Python. Задача
работы — попробовать разные способы ускорить этот цикл и честно
проверить, реально ли они дают ускорение:

1. **Потоки** (`threading`) — казалось бы, чем больше потоков, тем быстрее.
   На деле в Python это не так: из-за GIL (Global Interpreter Lock —
   внутренняя блокировка интерпретатора) в один момент времени выполняется
   только один поток на одном ядре, поэтому потоки для тяжёлых вычислений
   почти не ускоряют код.
2. **Процессы** (`multiprocessing`) — у каждого процесса свой GIL, поэтому
   они реально параллелятся на разных ядрах, но за это приходится платить:
   запуск процесса и передача данных между ними (сериализация) — недёшевы.
3. **Cython** — тот же код, но переменные объявлены с явными C-типами и
   компилируются в машинный код через C. Ускоряет саму арифметику, но
   только её — вызов произвольной Python-функции внутри цикла всё равно
   остаётся "медленным".
4. **nogil** — приём в Cython, который явно снимает GIL на время
   вычислений в C. Тогда потоки наконец-то начинают реально ускорять код,
   т.к. могут исполняться параллельно, а не по очереди.

Все цифры в отчёте — реальные замеры времени на этом компьютере, а не
теория. Итог по каждому пункту, с таблицами — в [`REPORT.md`](REPORT.md).

## Что означает каждый файл

| Файл | Что делает |
|---|---|
| `integrate.py` | Сама функция `integrate()` — считает интеграл обычным циклом. Обязательное задание: докстринг с описанием, аннотации типов, 2 примера прямо в докстринге (doctest) |
| `test_integrate.py` | Автотесты для `integrate()`: проверяют, что известные интегралы считаются правильно и результат не разваливается при изменении числа итераций |
| `bench_iter1.py` | Замеряет, сколько времени работает `integrate()` при разном числе итераций |
| `integrate_threads.py` | Та же задача, но разбитая на несколько потоков (`ThreadPoolExecutor`) |
| `integrate_processes.py` | Та же задача, но разбитая на несколько процессов (`ProcessPoolExecutor`) |
| `bench_iter23.py` | Сравнивает время работы потоков и процессов при 1, 2, 4, 6, 8 воркерах |
| `profile_integrate.py` | Профилировщик (`cProfile`) — показывает, на что именно уходит время внутри функции |
| `integrate_cython.pyx` | Тот же алгоритм, переписанный на Cython (с C-типами) |
| `setup_cython.py` | Скрипт сборки `integrate_cython.pyx` в готовый модуль (.pyd/.so) |
| `integrate_cython.html` | Отчёт Cython о том, какие строки кода остались "медленными" (обращаются к Python), а какие стали чистым C — генерируется автоматически при сборке |
| `bench_iter4.py` | Сравнивает скорость чистого Python и Cython-версии |
| `integrate_nogil.pyx` | Cython-версия, которая явно освобождает GIL во время вычислений (`with nogil`) |
| `setup_cython_nogil.py` | Скрипт сборки `integrate_nogil.pyx` |
| `integrate_nogil.html` | Тот же отчёт Cython, но для nogil-версии |
| `bench_iter5_nogil.py` | Замеряет реальное ускорение потоков благодаря nogil (в т.ч. на free-threaded интерпретаторе Python) |
| `bench_iter5_threads_vs_processes.py` | Сравнивает потоки (nogil) и процессы на одинаковой Cython-функции |
| `sync_primitives_demo.py` | Разбирает вопрос "а нужен ли тут мьютекс/семафор" — показывает на примере, когда он нужен, а когда нет |
| `REPORT.md` | Полный отчёт: все таблицы с цифрами и разбор каждого пункта задания |

## Как это запустить

Понадобится Python (лучше 3.11 или новее) и, для Cython-части — компилятор
C (на Windows — например, MinGW-w64, ставится через `winget install
BrechtSanders.WinLibs.POSIX.UCRT`).

Проверить базовую часть (без Cython) можно сразу:

```bash
git clone https://github.com/skypriority/lab10_1s.git
cd lab10_1s

python -m unittest test_integrate -v   # автотесты
python -m doctest integrate.py -v      # примеры из докстринга
python bench_iter1.py                  # замеры времени, чистый Python
python bench_iter23.py                 # сравнение потоков и процессов
```

Чтобы прогнать Cython-часть (итерации 4-5), нужно сначала собрать
расширения:

```bash
pip install cython setuptools
python setup_cython.py build_ext --inplace
python setup_cython_nogil.py build_ext --inplace
```

На Windows, если сборка ругается на отсутствие компилятора, укажи явно:

```bash
python setup_cython.py build_ext --inplace --compiler=mingw32
```

После сборки:

```bash
python profile_integrate.py
python bench_iter4.py
python bench_iter5_nogil.py
python bench_iter5_threads_vs_processes.py
python sync_primitives_demo.py
```

Для честной проверки nogil-ускорения (итерация 5) лучше запускать на
free-threaded интерпретаторе Python (сборка с отключаемым GIL,
появилась в Python 3.13):

```bash
uv python install cpython-3.13.15+freethreaded-windows-x86_64-none
PYTHON_GIL=0 python3.13t bench_iter5_nogil.py
```

Если такого интерпретатора нет — скрипты всё равно запустятся на обычном
Python, просто ускорение от потоков будет немного скромнее (см. таблицы
в REPORT.md — там показана разница между обычной и free-threaded сборкой).
